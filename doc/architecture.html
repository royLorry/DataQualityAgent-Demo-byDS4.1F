01

设计原则

五条原则逐字锚定规范 §1.2，并转译为可判定的架构约束，作为全篇设计的裁决依据。

需求
  • IT 实现与业务解耦
  • 业务人员可自编排
  • 产出物可审计复用
→
设计
  • P1~P5 作为硬约束
  • 每条映射到具体机制
  • 违反即评审阻断
→
验收口径
  • 逐条可追溯到模块
  • 无"Agent 直写业务库"
  • 无"全局塞知识"
P1业务活动用户自编排

Agent/Task/Skill/Tool 的编排是用户（业务人员）的活动，不是开发者写死的代码。

约束：编排 = 持久化配置数据，运行期读取，非源码
P2业务数据持久化由 Tool 调用

Agent 不直接把业务数据当自己的记忆/状态；落库一律通过 Tool 原子调用。

约束：State 不含业务产出物，落库仅经 probe.upsert 等
P3规则/探针是业务产出物

规则与探针是一等业务资产，可版本化、可审计、可复用。

约束：Standard/Rule/Probe 独立建模 + version
P4执行器用现成工具

执行引擎不重复造轮子，复用 LangGraph/LangChain 生态与既有调度器。

约束：StateGraph + trim_messages + APScheduler/Celery
P5知识加载是 Planner 的职责

知识不是全局塞进上下文，而是在规划阶段由 Planner 按 Task 白名单按需加载。

约束：加载发生在 knowledge_load 节点，非全局注入

06

消息压缩机制

消息上下文按 Hot/Warm/Cold 三区存储，五个压缩时机触发，复用 LangChain trim_messages 与 SummarizationMiddleware。

需求
  • 长会话不爆上下文
  • 关键节点留存语义
  • 复用生态、不造轮子
→
设计
  • 三层分区存储
  • 5 个压缩时机
  • trim_messages token 计数
→
验收口径
  • 超阈值自动降级旧消息
  • 系统提示常驻不被裁
  • 冷区可检索/可嵌入
热区 HotHOT

最近 N 轮原文保留，参与即时推理。zone=HOT

温区 WarmWARM

被裁消息摘要回填，保留关键结论。zone=WARM

冷区 ColdCOLD

历史归档嵌入，按需向量检索。zone=COLD

▲ 原文 → 摘要 → 归档嵌入的单向降级；token 预算逐层压缩

五个压缩时机（规范 §4.4）

① 轮次阈值触发 ② Token 阈值触发 ③ 子活动切换时 ④ HITL 中断点 ⑤ 任务 Finish 后

LangChain trim_messages 用法

python · 消息裁剪（保留最近 / 系统常驻 / token 计数）from langchain_core.messages import trim_messages

trimmed = trim_messages(
    messages,
    token_counter=tiktoken_counter,   # ② Token 阈值触发
    max_tokens=6000,                 # 预算上限
    strategy="last",                # 保留最近 → 构成 Hot 区
    start_on="human",
    include_system=True,             # 系统提示常驻，不被裁
)
# 被裁掉的旧消息 → SummarizationMiddleware 生成摘要写回 Warm 区
# Warm 区超预算再降级 → 归档嵌入 Cold 区；message.zone 记录分区
压缩发生在特定节点边界（③④⑤），与 DAG 主干对齐：execute_subtask 完成、gate_subtask 中断、finish_check 通过时各触发一次。

State TypedDict（四字段 · add_messages reducer）

python · langgraph State 定义from typing import TypedDict, Annotated
from langchain_core.messages import AnyMessage
from langgraph.graph.message import add_messages

class State(TypedDict):
    # 消息上下文（会话级，可压缩）
    messages: Annotated[list[AnyMessage], add_messages]
    # 执行上下文：DAG 状态、当前节点、变量、重试计数
    execution: dict
    # 知识上下文：Planner 加载片段（含来源/权限标记）
    knowledge: list
    # 配置上下文：Agent/Task/Skill/Tool 定义、路由规则、Gate 策略
    config: dict

建图 + HITL（interrupt / Command.resume）

python · StateGraph 编译与人工中断恢复from langgraph.graph import StateGraph, END
from langgraph.checkpoint.memory import MemorySaver
from langgraph.types import interrupt, Command

def gate_subtask(state: State):
    # HITL：中断等待人工确认，返回值来自 Command(resume=...)
    decision = interrupt({
        "task": state["execution"]["current_task"],
        "gate": "HUMAN",
    })
    return {"execution": {**state["execution"], "gate_result": decision}}

builder = StateGraph(State)
builder.add_node("router_stage1_state", router_stage1_state)
builder.add_node("knowledge_load", knowledge_load)      # Planner 职责 (P5)
builder.add_node("execute_subtask", execute_subtask)     # ReAct loop
builder.add_node("gate_subtask", gate_subtask)
# 子活动未通过 → 回 execute_subtask；通过 → 前进 finish_check

graph = builder.compile(checkpointer=MemorySaver())  # 生产: PostgresSaver

# 运行态恢复人工中断：
graph.invoke(Command(resume={"approved": True}), config={"configurable":{"thread_id": tid}})
Checkpointer：原型用 MemorySaver，生产用 PostgresSaver；PostgresSaver 使 HITL 中断可跨进程恢复。

执行引擎（L2）

Executor 以 ReAct 循环驱动 Skill→Tool；Planner 负责知识加载与规划；Gate 负责子活动与整体判定；失败重试与 HITL 中断内嵌其中。

需求
  • 通用引擎不绑业务
  • 失败可重试可恢复
  • 关键节点可人工介入
→
设计
  • 三角色分工
  • ReAct 循环 + 重试计数
  • interrupt 挂起
→
验收口径
  • 重试上限可配
  • Trace 记录 Tool/LLM
  • Tool 落库非 Agent 直写

三角色职责

Planner规划者

知识加载（P5）、产出子活动 Task 序列 = DAG 骨架；决定加载哪些/多少知识。

节点：knowledge_load · plan_subtasks
Executor执行者

以 ReAct 循环执行子活动，调用 Skill→Tool；执行 Tool、观察结果、迭代。

节点：execute_subtask
Gate判定者

子活动结束与整体任务结束的判定；分 LLM 判断与人工确认（HITL）。

节点：gate_subtask · finish_check

ReAct 执行循环

THOUGHT
思考

依据 knowledge + 上轮 Observation 推理下一步

ACTION
行动

Skill→Tool 调用（sql.execute / python.run …）

OBSERVATION
观察

读取 Tool 返回，写入 Trace，判定是否收敛

▲ Thought → Action → Observation 循环至子活动完成；失败则 execution.retry_count++ 直至上限

失败恢复与 HITL 中断点

机制触发条件处理状态字段
Tool 失败重试Tool 返回 error / 超时指数退避重试，超上限转 Gate 人工execution.retry_count
子活动 Gate 不通过LLM 判定不达标回边到 execute_subtask 重跑execution.current_task
HITL 中断（Gate）gate_policy=HUMAN/BOTHinterrupt() 挂起，等待 Command(resume)State.messages + checkpoint
HITL 中断（Finish）finish_check 需人工确认同上，恢复后判定整体任务是否 Finishexecution.finish
意图为 HITL_RESUMEStage2 命中恢复意图Router 路由到 Command(resume=...)见 §03 路由表
全链路可观测：Tool 调用追踪 tool_name/入参/出参/耗时/状态/错误；LLM 调用追踪 model/prompt_tokens/completion_tokens/耗时/节点名（写 trace 表，前台 Trace 面板时间轴可视化）。

SQLAlchemy 2.0 代表模型（async · Declarative）

python · SQLAlchemy 2.0 Declarative（异步）import enum
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, relationship
from sqlalchemy import String, Text, Integer, ForeignKey, JSON
from sqlalchemy.dialects.postgresql import ENUM

class Base(DeclarativeBase): ...

class ProbeStatus(str, enum.Enum):
    DRAFT="DRAFT"; RUNNABLE="RUNNABLE"; SCHEDULED="SCHEDULED"

class Probe(Base):
    __tablename__ = "probe"
    id:            Mapped[Integer]   = mapped_column(primary_key=True)
    rule_id:       Mapped[Integer]   = mapped_column(ForeignKey("rule.id"))
    type:          Mapped[str]       = mapped_column(String(16))   # SQL / PYTHON
    code:          Mapped[str]       = mapped_column(Text)
    status:        Mapped[ProbeStatus] = mapped_column(
        ENUM(ProbeStatus, name="probe_status"), default=ProbeStatus.DRAFT)
    datasource_id: Mapped[Integer]   = mapped_column(ForeignKey("datasource.id"))
    runs: Mapped[list["ProbeRun"]] = relationship(back_populates="probe")

# 异步引擎：create_async_engine("postgresql+asyncpg://...")
# 业务数据落库一律经 Tool（probe.upsert），Agent 不直写（P2）
Alembic 迁移：所有 status/type/category 用数据库级 Enum，重命名走 op.execute 改类型；每次生成 revision 与 version 资产字段一同审计。
